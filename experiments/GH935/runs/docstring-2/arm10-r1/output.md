Combining two nested dictionaries with `overlay` taking precedence over `base` leaves both inputs untouched — but the result is not a deep copy. Anything the merge did not itself build is the original object from its source: a list, or a nested dict that appeared in only one of the inputs, comes back shared by reference. Mutating the result in place can therefore show up through `base` or `overlay`, so copy explicitly if the result will be mutated.

The merge descends only where *both* sides hold a `dict`. Everywhere else, `overlay`'s value replaces `base`'s outright: lists are not concatenated, sets are not unioned, and a scalar in `overlay` silently swallows an entire nested subtree in `base` — or the reverse — rather than raising on the type mismatch. Nor is there any sentinel for deletion. Every key present in `overlay` is applied, so an explicit `None` overwrites a real value with `None`; the only way to drop a key is to leave it out of `overlay` altogether.

What counts as a `dict` is decided by `isinstance`, which has two consequences. Subclasses such as `OrderedDict` and `defaultdict` do recurse, but they come back as plain `dict`s, losing subclass behaviour like a default factory. Mappings that are not `dict` subclasses at all are treated as opaque values and simply replaced. Key order follows `base`, with keys unique to `overlay` appended in their own order.

Depth is bounded by the interpreter's recursion limit, and a structure containing a reference cycle will not terminate.
