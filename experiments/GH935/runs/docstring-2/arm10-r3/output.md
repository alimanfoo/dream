Takes two nested mappings and builds a new dict from them, letting `overlay` win wherever the two disagree. The merge is recursive, but under one condition only: when both sides hold a `dict` at the same key, those two dicts are merged; in every other case the overlay's value simply takes the base's place.

That single rule accounts for the rest of the behaviour. Lists are not concatenated and sets are not unioned, so a one-element list in the overlay displaces a ten-element list in the base. `None` in the overlay is an ordinary value like any other: it overwrites, rather than signalling that the base entry should be left alone. Nothing the overlay can say will delete a key. And when the two sides disagree about shape — a `dict` in the base where the overlay has a scalar, or the reverse — the losing subtree goes as a whole, with no attempt at a partial merge.

Neither argument is modified, but the new dict is only shallowly independent of them. Any value that wasn't itself merged as a `dict` is the same object in the result as in the input it came from, so a nested list or a custom object mutated after the call shows that change through both. If the inputs outlive the call, treat the result as read-only or deep-copy it.

Recursion is narrower than it may appear, too: only genuine `dict` instances trigger it. A `Mapping` implementation that isn't a `dict` subclass — the ordered and sorted dictionary types other libraries offer, for instance — counts as an opaque value and is replaced wholesale. Depth of recursion follows how deeply the inputs are nested, and a self-referential structure will never terminate.
