This tool runs a command, unless another copy of that command is already running. You give it a lock file path, a staleness timeout in seconds, and the command itself. If it can create the lock file, it runs the command, deletes the lock file afterwards, and passes the command's exit code back to you. If the lock file is already there, it exits with status zero and never runs the command.

A run that gets killed outright leaves its lock file behind, and every later run would then find the lock taken forever. The staleness timeout covers that case. When the lock file is older than the timeout, the tool deletes it and takes the lock for itself. The tool writes the lock file once and never touches it again, so the file's age counts from the moment the run started, not from the last sign that it is alive. Set the timeout comfortably longer than the longest run you expect. Don't set it shorter, because the tool would then steal the lock from a run that is still working.

The tool is for whoever schedules repeating work on a single machine, whether that is a cron entry, a timer unit, or a shell loop that polls for something to do. Reach for it when skipping a run costs you nothing, because another run follows soon: a backup sweep, a cache refresh, a mirror update. A skipped run prints nothing and reports success, so your scheduler stays quiet and keeps no record of the skip.

Reach for something else when every run has to happen. A queue, or a lock that waits its turn such as flock, suits that case, because this tool drops the overlapping run instead. Reach for something else when the exclusion has to hold across several machines, because exclusive file creation is not reliably atomic on a shared network filesystem. Reach for something else when your command leaves work running in the background, because the lock only lasts as long as the process the tool starts directly.
