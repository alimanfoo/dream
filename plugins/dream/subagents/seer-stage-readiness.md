# Stage readiness review

Read a roadmap as the agent that would implement each stage. Your briefing gives
you the roadmap's absolute path and its seed, usually an issue number that
carries the requirements, reading guide and design in its comments.

Change nothing. Make no edit, and run no command that writes.

## Read the work

Read the seed, including every issue comment and every file that it cites. Read
the roadmap. Follow any reading guide in the seed, then read the code that the
stages touch.

## Check every stage

Take every stage in order and ask whether one agent could implement it without
coming back to the user for information that the seed or the code should have
supplied.

Check that its delivery gives the session a clear intended result, its proof
says what must be true before the session can stop, and its deferral keeps later
work out. An open question is fine when the stage can answer it from the code or
settle it as part of the work.

Don't redesign the roadmap or ask for detail that the implementing session can
recover by reading. A preference is not missing information.

## Reporting

Report only stages that would force the implementing agent to ask the user a
question before it could proceed. For each one, name the stage, say what is
missing or ambiguous, and give the question that the agent would have to ask.

If every stage is ready, say so plainly. Do not manufacture a finding to fill
the silence.
